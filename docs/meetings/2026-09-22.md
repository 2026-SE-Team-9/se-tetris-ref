## 결정 사항

### 1. 요구사항 해석

사전에 정리한 요구사항 해석안을 검토했고, 큰 변경 없이 진행하기로 했다.
정리된 내용은 문서 형식으로 다듬어 저장소에 커밋한다.

### 2. 인터페이스 설계

공유된 인터페이스 설계안을 **기준으로 채택**한다.

- 세부적으로 조정이 필요한 부분(반환 타입 등)이 있다는 점은 인지했으나, 현 시점에서 확정하기 어렵다고 판단
- **구현을 진행하면서 실제로 문제가 될 때 수정**하는 방향으로 한다

### 3. 브랜치 운영

**`dev` 브랜치를 별도로 운영**한다.

```
작업 브랜치 → dev → (제출 시점) → main
```

- 평소 작업은 모두 `dev`로 모은다
- `main`은 제출 가능한 안정 버전으로 유지하고, 제출 시점에 `dev`에서 병합한다

### 4. 협업 도구

| 도구 | 담당 |
|---|---|
| **Jira** | 이슈 관리, 담당자 지정, 진행 상태 |
| **GitHub** | 코드, 브랜치, PR, 리뷰 |

- 회의 결과 등 기록은 GitHub 저장소에 둔다
- Jira를 추가로 활용하자는 의견이 있었고, GitHub의 보드와 형태가 유사해 큰 문제가 없을 것으로 판단
- GitHub Issues와 Projects는 사용하지 않고, **이슈는 Jira로 일원화**한다

### 5. PR 규칙 정립

PR 관련 규칙을 명문화할 필요가 있다는 의견에 따라, 저장소 설정 설명과 함께 **문서 형태로 작성**하기로 했다.

- 저장소 설정(브랜치 보호 룰셋 등)에 대한 설명을 공유했고, 룰셋은 바로 활성화하기로 함
- PR 리뷰 agent 프롬프트에도 일부 겹치는 내용이 있으나, 규칙 문서를 기준으로 삼는다

### 6. PR 리뷰 agent

이전에 언급된 PR 보조 agent에 대한 추가 설명을 공유받았다.

- Markdown 문서 형태의 프롬프트를 기반으로 LLM이 리뷰를 작성하는 방식
- 프롬프트 파일은 저장소에 함께 커밋되어 있다

### 7. 추가 기능

필수 요구사항을 먼저 구현하고, 아래 기능은 이후에 진행한다.

- 고스트 블럭 (착지 위치 미리보기)
- 홀드 기능

### 8. 회의 기록

회의 내용은 정리해둔 것이 있어 직접 작성하여 저장소에 커밋한다.

### 9. 빌드 설정

Gradle 설정은 **조작/빌드 담당**이 맡는다.
