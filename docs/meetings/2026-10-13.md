## 결정 사항

### 0. 지난 회의 이후 논의사항

- (10/8) GitHub Issue 재사용 논의

### 1. 1차 요구사항 작업 재배분 및 통합 테스트

기존에 1차 요구사항 구현 기한을 회의 전까지로 설정해두었지만 기한 내에 모든 요소들이 구현되지 못하였다. 따라서 추가로 기한을 3일 연장하고 작업을 재배분하여 10/16까지 남은 작업 완료 및 통합 테스트까지 진행하는 것으로 한다.

### 2. GitHub Issue 재사용

기존에는 Jira를 운영하고 GitHub Issue는 사용하지 않았지만 만일에 대비해 닫아놓지는 않은 상태였다. 2차 요구사항 문서에서 GitHub Issue가 작업내용 추적을 위해 필요하다고 명시되었으므로 Jira의 운영은 그대로 하되 이슈 기록을 GitHub Issue에도 남기는 것으로 변경한다.

### 3. 프로젝트 저장소 이름 및 설명 수정

현재 프로젝트 저장소는 기존의 참조 코드의 저장소를 clone한 것을 사용하고 있었으므로 이름과 설명 역시 참조 코드를 설명하는 내용으로 되어 있다. 이 내용들의 수정은 정해진 양식이나 명세가 없으므로 중간 평가 전에만 수정해두면 충분하다는 정도로 정리해둔다.

### 4. legacy 폴더 삭제

1차 요구사항의 구현이 진행되며 legacy 폴더에 존재하는 참조 코드의 제거가 가능해졌다. 요구사항을 구현한 이후 코드 정리와 동시에 삭제한다.

### 5. 2차 요구사항 세부사항

2차 요구사항 중 회의로 결정한 세부사항은 다음과 같다.

- 삭제 애니메이션은 표현 중 게임을 일시정지 후 연출하는 것으로 한다. 이에 맞춰 애니메이션을 표현하는 게임 상태를 추가한다.
- 스코어보드는 모드별로 따로 구분해서 표현한다.
- 난이도 설정은 일반 모드와 아이템 모드 모두에 적용된다.
- 무게추 아이템의 동작 방식은 아이템이 고정되었을 때 애니메이션과 유사하게 일시정지 상태에서 처리한다. 바닥에 착지한 후 그대로 유지된다. 점수는 아이템으로 삭제한 칸 * 10점을 부여한다.
- 추가 아이템으로는 스코어와 관련된 아이템이나 폭발로 주변 칸을 삭제시키는 아이템 등의 아이디어를 반영한다. 자세한 명세는 요구사항 문서에 기록한다.

### 6. 고스트, 홀드 기능

1차 요구사항 중 추가로 구현할 세부사항으로 기록한 고스트 블럭과 홀드 기능을 예상 구현 비용이 낮은 현 시점에 구현 여부를 결정하였다.

- 고스트 블럭은 1차 요구사항의 인터페이스에서 위치 계산 로직이 구현되어 있다. 게임의 규칙과도 충돌하지 않는 기능이므로 구현 시점에 따른 비용 차이가 크지 않을 것으로 판단된다. 따라서 고스트 블럭은 2차 요구사항과 함께 구현한다.
- 홀드 기능은 고스트 블럭과 달리 게임 규칙과 직접 연관되며 아이템의 홀드 여부, 추가적인 시각화와 조작 처리 등 구현에 필요한 작업이 고스트 블럭에 비해 비교적 많은 것으로 분석된다. 현재 상황은 명시된 요구사항의 구현에도 기한이 촉박하므로 현 시점에 홀드 기능을 추가로 구현하는 것은 불가능하다고 판단하여 구현 대상에서 제외한다.

### 7. 2차 요구사항 구현 기한

2차 요구사항은 10/27의 중간 평가를 위해 테스트 기간으로 여유를 두어 10/24을 기한으로 설정한다. 1차 요구사항의 기한과 달리 기한 미준수가 평가로 직결되므로 반드시 엄수하여야 한다.
